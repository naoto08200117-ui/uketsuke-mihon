# デザインシステム運用手順

最重要: 色・角丸・影・フォントは src/app/globals.css の @theme にあるトークンだけを使う。bg-[#123456] のような任意の値や、Tailwind 既定の色名は使わない。新しい値が必要なときは実装せず、理由を添えて提案し、承認を待つ。DESIGN.md がない、または空のときは、UI を実装せずに報告する。

## 手順
1. DESIGN.md と docs/要件定義書.md の第9章・第10章を読む。
2. 実装前に計画を出す: 使うトークン名、ASCII ワイヤーフレーム、この変更で目立たせる1か所（なければ「なし」）。
3. 承認後に実装する。画面の文字は要件定義書の第10章の文言一覧のとおりにする。
4. 下の「禁止パターン」と「機能面の最低ライン」で自分で点検し、違反を file:line 形式で報告する（なければ「違反なし」）。

## 禁止パターン（DESIGN.md で明示的に許可した場合を除く）
- グラデーション背景の画面中央に、小さな白いカードを浮かべる構成
- 紫・青・ピンクのグラデーション（背景・文字・ボタン）
- 見出しや項目の飾りとしての絵文字
- 英語の決まり文句の見出し、意味のない励まし文句
- 全要素に同じ大きな角丸とふんわりした影
- カードの中のカード
- 弾む動き、要素ごとのフェードイン、transition-all
- 純粋な黒・彩度のないグレーの多用、色付き背景の上のグレー文字
- アイコンライブラリ（必要ならテキストか手書きの小さな SVG）

## 機能面の最低ライン
- focus-visible: でフォーカスの枠を見せる。代わりの見た目なしの outline-none は禁止
- アニメーションは transform と opacity だけ。motion-reduce: で止める
- 文字と背景のコントラスト比は 4.5:1 以上
- 入力欄にはラベル、ボタンには読み上げ名
- 数字の並びは tabular-nums、省略記号は「…」
- 空状態とエラーには「次に何をすればよいか」を書く
- 幅 375px で横スクロールが出ない
