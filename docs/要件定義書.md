## 1. 目的

クラウドワークスの応募・プロフィールに載せる「触れる見本」。依頼主（小さなお店・会社の事務担当）が **30秒触って「うちの表もこうなる」と分かる** ことだけを目的にする。

- 架空の料理教室「みほん料理教室（サンプル）」の体験レッスンの受付を、スプレッドシートから Web アプリにした形を見せる
- 見せたいのは技術ではなく「いつもの表がどう楽になるか」。機能を足すより、**前後の比較（④）とスマホで見やすい一覧（②）** に時間を使う
- **応募文・プロフィールに載せる URL は `/compare/`（前後の比較）**。最初に「前と後」を見せ、ヘッダーのリンクから申込・管理一覧を触ってもらう
- 1週間で「触れる」ところまで作って止める。機能は増やさない

### 静的書き出しで使えないもの（GitHub Pages はファイルを置くだけの場所）

| 使えない | 代わり |
|---|---|
| API Route・Server Actions・`headers()`・`cookies()`・ミドルウェア・`next.config` の `headers()` | すべてブラウザの中（`'use client'`）で処理する |
| `[id]` の動的なページ（中身は localStorage にあり、書き出しの時に分からない） | 詳細は `/admin/detail/?id=...`（クエリ）。`useSearchParams` は `<Suspense>` で囲む。リンクは `next/link` の `href={{ pathname: "/admin/detail/", query: { id } }}`（文字列をつなげて URL を作らない） |
| `next/image` の画像の最適化 | `images: { unoptimized: true }`。画像は `import` して `next/image` に渡す（basePath が自動で付く） |
| セキュリティヘッダー（CSP・X-Frame-Options など） | 9章。`<meta>` で効くものだけ入れ、効かないものは「できない」と書く |

## 5. データ構造

```ts
// src/types/reservation.ts
type Status = "new" | "contacted" | "confirmed" | "done" | "canceled";
// 画面の名前：新規／連絡済み／確定／完了／キャンセル

type ChangeVia = "form" | "button" | "undo" | "csv" | "seed";
// きっかけ：申込フォーム／ボタン／1つ前に戻す／CSV の読み込み／架空のデータ

type StatusChange = {
  from: Status | null; // 前の状態。申込・CSV の読み込みの行は null。null があってよいのは1行目だけ。1行目が null でなくてもよい（50行に切り詰めた後）
  to: Status;          // 次の状態
  at: string;          // toISOString() の形（例 "2026-10-26T13:10:00.000Z"）。表示は日本時間
  via: ChangeVia;
};

type Reservation = {
  id: string;          // ^[A-Za-z0-9-]{1,64}$。新しい申込は crypto.randomUUID()。架空の10件は "seed-01"〜"seed-10"
  name: string;        // 前後の空白を除いて1〜30字。改行なし
  email: string;       // 前後の空白を除いて0〜100字。空なら ""
  phone: string;       // 半角に直した後 0〜13字（数字とハイフン、数字は10〜11桁）。空なら ""。email と phone のどちらかは必ず入っている
  lessonDate: string;  // "YYYY-MM-DD"。src/lib/lessons.ts の開催日（7日）のどれか
  people: 1 | 2 | 3 | 4;
  request: string;     // ご要望 0〜200字。改行可
  status: Status;
  memo: string;        // お店のメモ 0〜500字。改行可
  createdAt: string;   // 申込日時 toISOString() の形
  updatedAt: string;   // 最後に状態を変えた日時 toISOString() の形
  history: StatusChange[]; // 1〜50行
};

type ReservationStore = { version: 1; reservations: Reservation[] }; // 最大300件

// src/lib/lessons.ts（コードに固定。画面からは変えない）
type Lesson = { date: string; capacity: number }; // 定員はすべて8人。曜日は持たず dateFormat.ts で計算する
```

- localStorage のキー：`uketsuke-mihon.v1`（値は `ReservationStore` の JSON）
- 文字数は入力欄の `maxLength` と同じ数え方（`string.length`。絵文字は2字）
- 容量：1件およそ1KB、300件で約300KB。保存に失敗したら S-01（10章）

### 読み込み時の検証（`src/lib/reservationValidate.ts`。localStorage と CSV の両方で使う）

- **確かめた項目だけで新しいオブジェクトを組み立てる**。元のオブジェクトを `...` で広げたり、そのまま使ったりしない。知らない鍵（`__proto__`・`extra` など）は捨てる
- 1件ずつ：id の形・型・文字数（前後の空白を除いた後）・メールの形・電話の形（半角に直した後）・`lessonDate` が開催日か・`people` が1〜4の数か・`status` の値・`createdAt`/`updatedAt` が `toISOString()` の形か・`history`（1〜50行、各行の `from`/`to`/`at`/`via` の値、**`from: null` があってよいのは1行目だけ。1行目が null でなくてもよい（50行に切り詰めた後）**、最後の行の `to` が `status` と一致）
- 通らない件は捨てて S-03
- **同じ id が2件以上あれば、先の1件を残し、2件目からを捨てて S-03**
- **検証を通った件が300件を超えたら、先頭から300件を残し、301件目からを捨てて S-03**
- 全体が読めないとき（JSON が壊れている・オブジェクトでない・`version` が1でない・`reservations` が配列でない）は、架空の10件を表示して S-04（保存はしない）
- 何を上書きするかは 10章「壊れたデータの扱い」

### 状態の進め方（`src/lib/status.ts`）

- `next = { new: "contacted", contacted: "confirmed", confirmed: "done" }`。キャンセルは new・contacted・confirmed から。完了とキャンセルには次がない

## 8. CSV の形

- 1行目は見出し。列の並びは自由。知らない列は無視する
- **見出しは、先頭の BOM（U+FEFF）と各セルの前後の空白（`trim()`）を除いてから比べる**
- 必ず要る見出し：`お名前`・`メール`・`電話`・`希望日`・`人数`。なくてもよい見出し：`id`・`ご要望`・`状態`・`メモ`・`申込日時`・`更新日時`
- 書き出す列の順：`id,お名前,メール,電話,希望日,人数,ご要望,状態,メモ,申込日時,更新日時`
- 状態：日本語の名前（空なら「新規」）
- 文字コード：読み込みは UTF-8（BOM あり・なし）をまず試し、壊れていれば Shift_JIS（Excel の「CSV（コンマ区切り）」の形）として読む（`TextDecoder` の `fatal: true` → `"shift_jis"`。追加ライブラリなし）。両方だめなら V-15
- 書式：RFC 4180（`"` で囲んだ中のコンマ・改行、`""` は `"`）。パーサーは自分で書く（`src/lib/csvParse.ts`。T07）。最後まで `"` が閉じていなければ V-15
- **行番号**：見出しを1行目とした、CSV のレコードの番号（Excel で開いたときの行番号と同じ。`"` の中の改行では増えない）。すべてのセルが空の行は、読み込みも理由の表示もせず飛ばすが、番号は数える
- **行数の上限**：見出しを除いて1000行まで（空の行も数える）。超えたら V-15
- 各セルは前後の空白を除いてから確かめる（ご要望・メモは除かない）。メール・電話は F2 と同じ直し方（電話の全角→半角）
- **表計算ソフトの数式の注入の対策**：書き出しで、`=` `+` `-` `@` タブ・CR で始まる値の前に `'` を付ける（`src/lib/csvFormat.ts`。T06）。読み込みでは、`'` の直後がこれらの文字なら `'` を外してから検証する（`src/lib/csvImport.ts`。T07）
- `id` がない行・`id` が空の行は新しい id にする。`id` が `^[A-Za-z0-9-]{1,64}$` に合わない行は理由「id の形が違います」で捨てる。同じ CSV の中で同じ id が2回出たら、2回目を「同じ id が2回出てきます」で捨てる
- 状態の記録：読み込んだ件は1行 `{ from: null, to: CSV の状態, at: 読み込んだ時刻, via: "csv" }` で始める（CSV に記録は入れない。表示は R-06 の「CSV から読み込み」）
- 行の検証の理由（V-20〜）は 11章。定員は読み込みでは止めない（今のシートに定員を超えた日があっても読み込め、F5 の「定員超え」で見える）

### 日付と日時（`src/lib/dateFormat.ts`。Excel で開いて保存し直すと形が変わるため、どれでも読める）

| 項目 | 書き出す形 | 読める形 |
|---|---|---|
| 希望日 | `YYYY-MM-DD`（例 `2026-12-05`） | `YYYY-MM-DD`／`YYYY/M/D`（0 を付けても付けなくてもよい：`2026/12/5`・`2026/12/05`） |
| 申込日時・更新日時 | 日本時間の `YYYY-MM-DD HH:mm` | `YYYY/M/D H:mm`（例 `2026/10/2 9:15`）／`YYYY-MM-DD HH:mm`／どちらも後ろに `:ss` があってもよい／ISO 8601（`YYYY-MM-DDTHH:mm`〜`:ss.sss`。後ろに `Z` か `+09:00` などの時差があればそれで読み、なければ日本時間）。空なら読み込んだ時刻 |

- **時差の書いていない形は、すべて日本時間（+09:00）として読む**。PC の時間帯の設定に左右されないように、`new Date(文字列)`・`Date.parse` は使わない。正規表現で年・月・日・時・分を取り出し、`Date.UTC(年, 月-1, 日, 時-9, 分)` で計算する（日本は夏時間がない）
- 月1〜12・日がその月にある日・時0〜23・分0〜59・秒0〜59 でなければ「日時の形が違います」（希望日は「開催日にない日付です」）。日がその月にあるかは、`Date.UTC` で作った日を `getUTCFullYear/Month/Date` で読み戻して同じか比べる
- 書き出し・画面の表示も、`Intl`・`toLocaleString` を使わず、UTC の時刻に9時間足して `getUTC*` で読み、文字を組み立てる（書き出しの時に描く画面でも、見る人の PC でも同じ文字になる）

## 10. 保存（localStorage）と Hydration の決まり

shiryo-maker と同じ形。静的書き出しでは書き出しの時（サーバー側）に1回描くので、そこで localStorage を読むと Hydration エラーになる。

### 読む

- localStorage を触ってよいのは `src/lib/reservationStorage.ts` の関数だけ。それを呼ぶのは `src/lib/useReservations.ts` と `'use client'` の部品だけ
- `useSyncExternalStore` で読む。**`getServerSnapshot` は毎回同じ定数（「読み込み中」を表す1つの値）を返す**。`getSnapshot` は**同じ文字列なら同じオブジェクトを返す**（前の文字列と結果を覚えておく。毎回 `JSON.parse` した新しいオブジェクトを返すと無限に描き直す）。lint の `react-hooks/set-state-in-effect` に当たらない形にする
- **メモリの値があるとき（S-01 の後・S-02 のとき）は、`getSnapshot` は localStorage ではなくメモリの値を返す**（変わらなければ同じオブジェクト）。メモリの値が変わったら、同じタブの購読者に知らせる
- 購読（`subscribe`）は、別のタブの変更（`storage` イベント）と、**同じタブでの保存・メモリの値の変更の知らせ**（`reservationStorage.ts` が持つ購読者の一覧。`storage` イベントは同じタブには来ないため）の両方
- 読み込み中は一覧・フォームの選択肢・残り席を出さない（高さだけ確保した空の場所）
- localStorage が空なら架空の10件を表示する。**読み込んだだけでは書かない**

### 書く（2つのタブでの上書きの取り合いを防ぐ）

1. 変更は「今のデータ → 新しいデータ」の関数で表す（例：「id の申込を、**押した時に見えていた状態（ボタンの元の状態）**から次にする」。ボタンの元の状態は、押したボタンから関数に渡す）。画面が持っている古いデータを丸ごと書かない
2. **保存の直前に読み直して検証する**（メモリの値があればそれ、なければ localStorage。下の「壊れたデータの扱い」も同じ）
3. その上に変更を当てる。残り席・F-17・F-18・V-14・R-07 の確かめも、読み直したデータで行う。**変える必要がなければ（申込がない・状態がボタンの元の状態と違う・次がない・押せない形）書かず、購読者に知らせて描き直すだけにする**（F7・F11・F12・F13）
4. `setItem` する。成功したら、同じタブの購読者に知らせる
5. 架空のデータに戻す・置き換えるは、読み直しても結果は同じ（丸ごと置き換え）。置き換えるは、読み直したデータで V-14 を確かめ直してから書く（F16）

### 失敗の分け方（`alert()`・`confirm()` は使わない）

| 起きたこと | 見分け方 | 出すもの | その後 |
|---|---|---|---|
| 保存の場所が使えない | `window.localStorage` を触る・`getItem` で例外（サイトのデータを保存しない設定など） | 開いた時に S-02（出したまま） | 架空の10件を表示。変更はこのページのメモリにだけ持ち、`getSnapshot` はメモリの値を返す（S-01 は重ねて出さない） |
| 保存に失敗 | 読めるのに `setItem` で例外（空き容量がないなど） | S-01 | その変更はメモリに持ち、以後はメモリの値を「今のデータ」として表示（`getSnapshot`）と読み直しに使う。次に `setItem` が成功したらメモリの値を捨てる |
| 一部の件が読めない | 5章の検証で捨てた件がある | S-03 | 読めた件を表示 |
| 全体が読めない | 5章の「全体が読めないとき」 | S-04 | 架空の10件を表示 |

- `JSON.parse` と `localStorage` の操作はすべて `try/catch`

### 壊れたデータの扱い

- 開いただけでは上書きしない（壊れた値はそのまま残る）
- **利用者が最初に操作したとき**に、そのとき表示しているデータ（S-03 なら読めた件だけ、S-04 なら架空の10件）に変更を当てて上書きする。捨てた件はそこで消える（S-03・S-04 の文言で先に知らせている）

### そのほか

- 日付・日時の文字は `src/lib/dateFormat.ts` で組み立てる（8章。`Intl`・`toLocale*`・`new Date(文字列)`・`Date.parse` を使わない）。曜日は `new Date(Date.UTC(年, 月-1, 日)).getUTCDay()`
- `crypto.randomUUID()` と「今の時刻」（`Date.now()`）はブラウザ側の操作の中だけで使う（`https` と `127.0.0.1` は安全な場所の扱いなので使える）
- 前後の比較の右側は localStorage を使わず `seed.ts` を直接表示する（書き出しの時に描けるので Hydration の心配がない。日付の文字は `dateFormat.ts` なので書き出しの時とブラウザで同じ）
