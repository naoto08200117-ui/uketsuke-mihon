# CSP の meta を入れずに進めることにした

## 決めたこと

`layout.tsx` に CSP の `<meta httpEquiv="Content-Security-Policy">` を入れない。`<meta name="referrer" content="no-referrer">` は残す。要件定義書9章の「前に置けなかったとき」のとおり。

## 背景（なぜ決める必要があったか）

T01 で `layout.tsx` の `<head>` の先頭に CSP の meta を置き、`npm run build` で `out/index.html` を調べた（2026-10-30、Next.js 16.4.2）。

- 最初の `<script`：先頭から 350 文字目
- CSP の meta：先頭から 830 文字目

Next.js が `<head>` の先頭に、スタイルシートとスクリプトの読み込みを自動で入れるため、CSP の meta は最初の `<script` より後ろになった。CSP の meta は、それより前に書かれたスクリプトには効かない。効かない守りを「入れた」と見せないために外した。

## 検討した他の案と、選ばなかった理由

- 置き場所を工夫して前に出す：要件定義書9章で「直そうと試さず、止めて報告する」と決めている
- 書き出しの後に HTML を書き換えて CSP を先頭に入れる：作業の手順と道具が増える。1週間で作る見本の範囲を超える

## この決定による影響・注意点

- 「外のサイトのスクリプトを読み込まない」「外へ送らない」を CSP で強制できない。代わりに、`fetch`・外部のスクリプト・フォント・解析タグを入れない決まり（CLAUDE.md §10）と、React の通常の表示・`dangerouslySetInnerHTML` を使わない決まりで守る
- 要件定義書9章の「できないこと」に「CSP（meta が script より後ろになるため）」を足す案を nao さんに出す（要件定義書は nao さんの管理）
- T10 の合格基準④（CSP の違反が0件）は「対象外」と書く
