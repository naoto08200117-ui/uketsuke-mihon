# セキュリティ基礎ガイドの2つの決まりを、このアプリでは例外にした

## 決めたこと

`docs/セキュリティ基礎ガイド.md` の次の2つを、このアプリでは守らない。代わりの守りを置く。

| ガイドの決まり | このアプリ | 代わりの守り |
|---|---|---|
| 2-8「リポジトリはプライベートで作る」 | 公開リポジトリにする | 秘密の値と nao さんの個人情報を書かない（CLAUDE.md §10）。コミットのメールは GitHub の noreply にする。`.env` 系は作らない。最初の push の直後（どのチケットの後でも）に、要件定義書 T10⑦ の項目を GitHub で確かめる。T10 でもう一度確かめる |
| 3-4「`next.config` の `headers()` でセキュリティヘッダーを付ける」（5章チェックリスト No.10 も同じ） | `headers()` は書かない。`<meta>` で CSP と referrer だけを入れる | CSP は本番の書き出しのときだけ `layout.tsx` の `<head>` に入れる。referrer は `no-referrer`。付けられないもの（`frame-ancestors`・X-Frame-Options など）は、要件定義書9章の「できないこと」に正直に書く。ネットワークタブでヘッダーを確かめる No.10 は「対象外」とする |

## 背景（なぜ決める必要があったか）

- GitHub Pages を無料で使うためと、応募で作り方まで見せるために、リポジトリを公開する。このアプリは秘密の値（APIキーなど）を持たない
- 静的書き出し（`output: 'export'`）では `headers()` が効かない。GitHub Pages では、こちらからヘッダーを付けられない

## 検討した他の案と、選ばなかった理由

- プライベートリポジトリ＋有料プラン：見本のために費用をかけない。応募で作り方を見せられなくなる
- サーバーのある置き場所（ヘッダーを付けられるところ）：新しい登録が増える。nao さんは「今あるものを使う」と決めている

## この決定による影響・注意点

- 公開した中身は誰でも見られる。コード・`docs/`・コミットメッセージに本名・メールアドレス・住所を書かない
- CSP の `'unsafe-inline'` では、ページに紛れ込んだスクリプトを止められない。入力を使った攻撃（XSS）への主な守りは、React の通常の表示と `dangerouslySetInnerHTML` を使わないこと
- 他のサイトの枠の中に表示されること（クリックジャッキング）は防げない。守るべき本物のデータと取り消せない送信がないので受け入れる
