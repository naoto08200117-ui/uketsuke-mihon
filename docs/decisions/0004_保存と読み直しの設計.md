# 保存（localStorage）は1つのファイルに閉じ込め、useSyncExternalStore で読み、書く直前に読み直す形にした

## 決めたこと

- localStorage を触るのは `src/lib/reservationStorage.ts` だけ。外に出すのは次の4つ
  - `getReservationSnapshot`（今のデータ）・`getServerReservationSnapshot`（読み込み中の定数）・`subscribeReservations`（購読）・`updateReservations`（変更を当てて書く）
- 画面は `src/lib/useReservations.ts` の `useReservations()`（`useSyncExternalStore`）だけで読む
- スナップショットの形：`{ loading: true }`（書き出しの時と Hydration の時。毎回同じ1つのオブジェクト）か、`{ loading: false, reservations, notice }`。`notice` は `saveFailed`（S-01）・`unavailable`（S-02）・`partial`（S-03）・`broken`（S-04）・`null`
- `getSnapshot` は localStorage の文字列を毎回読むが、**前と同じ文字列なら前に作ったオブジェクトをそのまま返す**（覚えておく鍵は、空＝`e`・値あり＝`v`＋文字列・使えない＝`u`。先頭の1字で取り違えを防ぐ）
- **メモリの値**（S-01 の後・S-02 で書いた後）があれば、`getSnapshot` も読み直しもそれを返す。次に `setItem` が成功したら捨てる
- 購読は `storage` イベント（別のタブ）と、ファイルの中の購読者の一覧（同じタブ。保存の成功・メモリの値の変更・「変えるものがなかった」ときに知らせる）の両方
- 書くときは `updateReservations(change)` に「今のデータ → 新しいデータ」の関数を渡す。関数は**保存の直前に読み直して検証したデータ**を受け取り、変える必要がなければ `null` を返す（そのときは書かずに購読者へ知らせて描き直すだけ）
- 読むだけでは決して書かない。壊れた値（S-03・S-04）も、利用者が操作したときに「表示中のデータ＋変更」で上書きされるまで残る
- 検証（`reservationValidate.ts`）は、確かめた項目だけで新しいオブジェクトを組み立てる。同じ id の2件目から・301件目からは捨てる

## 背景（なぜ決める必要があったか）

- 静的書き出しは書き出しの時に1回描くので、そこで localStorage を読むと Hydration エラーになる（要件定義書10章）
- `getSnapshot` が毎回 `JSON.parse` した新しいオブジェクトを返すと、React が「変わった」と見て無限に描き直す
- 2つのタブで同じデータを触るので、画面が持っている古いデータを丸ごと書くと、別のタブの変更を消してしまう

## 検討した他の案と、選ばなかった理由

- `useEffect` の中で読んで `useState` に入れる：lint の `react-hooks/set-state-in-effect` に当たり、別のタブの変更の購読も自前で書く必要がある
- `use(browser())` と `<Suspense>`（Next.js の SPA の説明にある形）：別のタブ・同じタブの変更を知る仕組みがなく、要件の「購読」を満たせない
- 読み込みの時に壊れた値を直して保存する：要件の「読み込んだだけでは保存しない」に反する
- 書く関数に「新しい配列そのもの」を渡す：読み直しの後の確かめ（残り席・ボタンの元の状態など）ができない

## この決定による影響・注意点

- T03 からの変更は、すべて `updateReservations` に関数で渡す。関数の中で受け取った配列やオブジェクトを書き換えない（覚えておいたスナップショットを壊すため）。新しいオブジェクトを作って返す
- 「変えるものがない」ときに `null` を返すのを忘れると、何も変わらないのに保存してしまう
- S-02 のときは架空の10件（`seed.ts` の値そのもの）を表示する。メモリの値は書いた後にだけ作る
- 同じ id の判定は「検証を通った件どうし」で行う（1件目が壊れていて2件目が正しければ、2件目を残す）
